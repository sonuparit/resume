Prompt

I'm applying for a {{ Role }} position at this company: {{ CompanyWebsite }}      

`jd-keywords.yaml` contains all the important keywords, phrases and responsibilities, this company is looking for.

Purpose:
I want to know exactly which contents are taking unnecessary space, and where are they located in my resume, So I can better use those places to optimize my resume according to JD, to pass ATS.

Consider content non-relevant if it is unrelated, redundant, overly generic, or does not strengthen the candidate's fit for the target role according to `jd-keywords.yaml`

Instructions:

Use `jd-keywords.yaml` as the authoritative ATS filter and perform a transformation on `resume.yaml`.

Output the complete transformed file as downloadable `resume-correction.yaml` file. Never truncate, summarize, omit sections, or use `...`.

Rules for transformation:

1. Modify only:

  * `summary`
  * `skills`
  * `projects.bullets.text`
  * `experience.bullets.text[0-2]`
  
2. Wrap the transformed contents inside `<s>...</s>` tags.
3. Preserve the entire file exactly: structure, ordering, indentation, arrays, IDs, punctuation, spacing, and all unchanged content.
4. Never add, delete, rename, reorder, merge, split, abbreviate, paraphrase, or regenerate content. Copy unchanged lines verbatim from the source file.
5. Never fabricate experience, responsibilities, technologies, projects, certifications, employers, metrics, or achievements which are not present in `my-skills.yaml`.
6. Preserve valid YAML syntax. 

Rules for sentence transformation:

1. Applies to `summary`, `projects.bullets.text`, and `experience.bullets.text`.
2. Evaluate sentence-by-sentence.
3. Wrap only non-relevant, same or redundant sentences, experiences or responsibilities with `<s>...</s>`.
4. Leave relevant sentences, experiences or responsibilities unchanged.
5. Never strike through an entire paragraph unless every sentence, experience, or responsibility is non-relevant.

Rules for keyword or phrase transformation:

1. Applies to `skills`.
2. Evaluate every skill token and skill phrase independently.
3. Treat list items as containers, not as a single string.
4. For nested values inside parentheses, brackets, or comma-separated groups, evaluate each sub-skill independently.
5. Preserve separators and formatting exactly.
6. Wrap only non-relevant or redundant tokens or phrases with `<s>...</s>` tags. Never wrap an entire list item if only some sub-skills are non-relevant.

Perform a token-level transformation, not a rewrite.
